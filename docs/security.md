# Кот охраняет коробку. Не заменяет модель угроз.

## Границы доступа

Pawlish — single-tenant CRM. Все созданные администраторы имеют доступ ко всей клиентской и финансовой информации. Ролей, филиалов, изоляции пользователей и публичной записи нет. Не открывайте панель для недоверенных операторов. Приложение использует стандартные сессии и CSRF Laravel/Filament, вход закрыт авторизацией. Не используйте debug в сети.

- `.env`, базы, логи и бэкапы исключены из Git и build-контекста Docker. Секретов по умолчанию нет.
- `APP_KEY` должен быть случайным и постоянным. При HTTPS включите Secure cookies.
- Nginx исполняет через FPM только `index.php`, а скрытые файлы и другие PHP-пути недоступны. FPM слушает внутреннюю сеть Docker.
- Экспорт требует входа; ответы помечены `private, no-store`. CSV защищает текстовые поля от распространённых формульных префиксов, PDF не загружает удалённые ресурсы.
- База и резервные копии содержат персональные данные. Настройте права доступа, шифрование диска и срок хранения. Не отправляйте базу в публичный репозиторий.

## Telegram: бот без незваных гостей

1. Создайте своего бота через BotFather. Сохраните токен в настройках CRM.
2. Откройте личный чат с этим ботом и отправьте `/start`. Узнайте числовой ID личного чата через доверенный Telegram API-клиент (`getUpdates` при отсутствии webhook) и внесите его в поле «Ваш Chat ID» вручную. Не передавайте токен посторонним ботам и не вставляйте его в публичные логи.
3. Настройте шаблон и время напоминания. Планировщик опрашивает записи каждую минуту. Для обычных напоминаний входящий webhook **не обязателен**.
4. Если нужна ответная проверка `/start`, задайте случайный `TELEGRAM_WEBHOOK_SECRET` (символы A–Z, a–z, 0–9, `_`, `-`; 1–256 символов) и зарегистрируйте webhook через Telegram API `setWebhook` с параметрами `url=https://crm.example.com/api/telegram/webhook` и `secret_token`. Старый адрес `/telegram/webhook` из прежней инструкции неверен: Laravel добавляет `/api`.

Webhook без настроенного секрета закрыт, чужой чат и групповой чат отклоняются. Бот не меняет `master_chat_id` по входящему сообщению. Токен маскируется в панели, но хранится в базе в открытом виде для совместимости с Mani Webs. Ограничьте доступ к БД. Сообщения отправляются обычным текстом, не HTML; Telegram получает данные из шаблона. Удалите имя/цену из шаблона, если их не нужно передавать наружу.

Доставка не exactly-once: если Telegram принял запрос, но ответ потерялся, повторная попытка может продублировать сообщение. Уникальная очередь уменьшает риск, но не даёт абсолютной гарантии. Ошибки не включают токен или сырой ответ API. Существующая строка со статусом «отправлено» не пересылается автоматически при миграции.

## Зависимости

В этой версии сохранены lock-файлы исходного Laravel 12 / Filament 3 / Vite. CI выполняет `composer audit --locked --no-dev` и `npm audit --audit-level=high`. Проверки используют актуальные advisory-базы при запуске; отсутствие известных уязвимостей локально не подтверждено. Если audit обнаружит проблему, обновите зависимости и повторите полный CI перед внешним развёртыванием.

Этот проект не прошёл независимый penetration test и не обещает соответствия конкретному законодательству о персональных данных.
